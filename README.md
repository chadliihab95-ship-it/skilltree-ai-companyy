# SKILLTREE — AI Company OS

واجهة تشغيل لشركة تعتمد على وكلاء الذكاء الاصطناعي. تتضمن لوحة قيادة، 7 أقسام، 28 وكيلاً، مهام، سجل نشاط، موافقات بشرية، ومساعد CEO عبر Gemini.

## المتطلبات
- Node.js 20+
- مفتاح Gemini اختياري لتفعيل استدعاءات النموذج
- مشروع Supabase اختياري لتفعيل التخزين والمصادقة

## التشغيل
```bash
npm install
cp .env.example .env
# ضع GEMINI_API_KEY داخل .env محلياً فقط
npm run dev
```
افتح رابط Vite الذي يظهر في الطرفية. واجهة API على `http://localhost:8787`.

## البناء
```bash
npm run build
npm run start
```
بعد البناء، انشر مجلد `dist` كواجهة ثابتة، وشغّل خادم Express كخدمة منفصلة. اضبط CORS على نطاق الواجهة قبل النشر العام.

## Google AI Studio
يمكن استيراد ملفات المشروع إلى Build mode. استخدم `src/main.tsx` كنقطة دخول للواجهة. استدعاءات Gemini تمر عبر `/api/ceo/chat` على الخادم. في بيئة لا تدعم Express، انقل منطق الخادم إلى وظيفة server-side مدعومة، وأضف المفتاح في Secrets. لا تضعه في متغير يبدأ بـ `VITE_`.

## Supabase
نفّذ `supabase/schema.sql` في SQL Editor. أنشئ مستخدماً من Auth، ثم مؤسسة وعضوية لها. أضف `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` إلى بيئة الواجهة عند تفعيل العميل. سياسات RLS مفعلة على الجداول. لا تستخدم Service Role في المتصفح.

## ما هو جاهز وما يحتاج استكمالاً
- جاهز: واجهة تشغيل تفاعلية، بيانات أولية للأقسام والوكلاء، إنشاء/تحديث المهام محلياً، طابور موافقات محلي، سجل نشاط، API Gemini خادمي.
- يحتاج إعداداً: تسجيل دخول Supabase، ربط بيانات الواجهة بالجداول، عامل تنفيذ مهام دائم (queue/worker)، مزودات الأدوات الخارجية، حدود الاستخدام والمراقبة والنسخ الاحتياطي.
- لا تنفذ الوكلاء إجراءات خارجية تلقائياً؛ الموافقات البشرية مطلوبة قبل أي إجراء حساس.

## أمان
المستودع عام. لا ترفع `.env` أو مفاتيح أو بيانات مرضى/عملاء. غيّر أي مفتاح تم تسريبه فوراً.
